# 窗口内识别（1.2.0）

在“时间线 → 编辑动作 → 图像识别”中设置“识别范围”：

- **桌面**：保持原有所有显示器搜索，旧 MR 缺少范围字段或字段为 null 时使用此模式。
- **指定窗口**：选择此范围后才显示“识别窗口”按钮，点击从列表选择目标，保存后仅搜索该窗口的当前内容区。鼠标悬浮窗口按钮可查看完整标题和进程名；切回桌面时隐藏按钮，当前编辑器中的窗口描述保留。

“识别”预览接收当前尚未保存的模板、阈值、缩放开关和窗口范围；打开编辑器或预览不枚举目标、不截图，不自动保存动作。窗口列表只在用户主动选择时读取。配置窗口模式但未提供有效窗口描述时，保存、加载和播放预检都会拒绝。

## 定位与状态要求

MR 仅保存 `searchScope` 和 `searchWindow`（进程名称、窗口标题、窗口类），不保存句柄、PID 或窗口坐标；跨目录另存为保留这些设置，窗口描述使用独立副本。图片路径及外部素材要求不变。

首次实际执行节点时才定位窗口：先按进程名称和窗口类筛选，再优先使用唯一标题匹配。标题改变时，只有进程名称与窗口类候选唯一才允许使用；候选不唯一会报错，不自动取面积最大的窗口。首次绑定后，在该次播放中继续校验同一运行时窗口的身份，标题变化可继续；关闭后不会悄悄换到另一窗口。开始下一次播放重新定位，位置缓存仍按原规则保留或失效；加载 MR、开始新录制会清空窗口绑定及位置提示。

本版使用可见屏幕匹配，**目标需要在前台且未最小化**，不支持被遮挡或最小化时的后台窗口识别。识别不调用窗口激活、不恢复窗口、不模拟按键，也不会每次抢焦点；请使用已有宏目标窗口激活流程，或在执行到该节点前手动显示目标。其他置顶窗口、系统覆盖层等仍可能遮挡内容，需要保持目标可见。

找不到窗口、多个候选无法唯一定位、窗口不可见/失去前台、显示器布局变化，以及捕获或匹配前后检测到客户区位置/大小变化，均按识别运行错误处理并结束该次播放，明确提示原因。不会使用桌面代替窗口，不走普通“图片未找到”分支，也不触发失败点击。窗口有效、图像未出现时才执行配置的失败行为，包括重试、执行、终止、跳转或在独立坐标点击后执行/终止。

## 搜索范围与移动

局扫、扩大局扫及竞速中的完整搜索都限制在同一份当前窗口内容区，窗口外同图不参与匹配。每个捕获阶段以及匹配完成后检查窗口身份与客户区；命中返回的仍是屏幕逻辑坐标，已有中心/随机点击继续使用当前结果。

失败点击是另外显式设置的固定屏幕 X/Y 坐标，不以窗口为原点、不随窗口移动，也不限制在识别客户区；它不使用局扫缓存或上次命中位置。成功点击仍在当前实际命中范围内执行。

每次执行节点都重读窗口位置和尺寸。窗口移动或调整大小后，范围跟随当前客户区，旧范围的位置提示失效，再在新范围内完整搜索；没有实现相对窗口坐标的命中位置推移。桌面录制选区提示不用于窗口模式，桌面和窗口模式切换不会复用错误范围的提示。竞速、停止、原生调用后台收尾与 delay 保持此前已确认的规则，不增加等待上一轮识别结束的屏障。

客户区跨屏时分别截取各屏幕内的可见部分，使用每块屏幕的 DPI 转换，不拼接屏幕接缝，也不搜索边框、系统标题栏或窗口外内容；自绘标题栏可能属于客户区。捕获采用 Java 17 Robot 的逐屏物理变换并检查原点/宽高分别舍入造成的边缘误差，局扫起点变化后也重新约束。非整数 DPI 下会向内取整，可能少量裁去边缘像素，模板应留少量边距。

预览在所选范围内完整搜索并显示多结果，不使用播放的位置缓存。窗口模式下本程序保持隐藏直到匹配结束，避免恢复界面抢走前台导致当前请求失效；桌面模式仍按原方式在采集后恢复。预览不发送点击或执行分支。

## 与窗口截图的区别

[指定窗口截图](window-capture.md) 是采集页的临时窗口选择，用户点击截图时可尝试恢复并前置目标，目标不写入 MR。本文是图像动作中的持久搜索范围，运行时不激活窗口。两者独立，采集页所选窗口不会自动改变已有图像动作或宏的录制/播放目标。

本轮没有新增依赖或升版，旧发行包不包含新功能。自动验证使用合成画面和窗口服务替身；真实 Windows 11、150% DPI 下的目标定位、焦点、遮挡、移动/缩放、跨屏及停止恢复仍需人工验收。[测试记录](automated-tests.md) 保留最终结果与日志。坐标变换参考 [OpenJDK 17 的逐屏 Robot 变换](https://github.com/openjdk/jdk17u/blob/master/src/java.desktop/share/classes/sun/java2d/SunGraphicsEnvironment.java)。
