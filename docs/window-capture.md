# 指定窗口截图（1.2.0）

采集图像页点击“指定窗口”，从窗口列表选择目标；支持刷新、双击或“选择窗口”确认，取消保留原选择。列表后台读取，不显示本程序窗口或 DWM 隐藏窗口；最小化但仍可见的窗口可被选择。确认只更新当前采集页，点击“截图”才尝试恢复并前置目标。选择“使用屏幕”返回原来的鼠标所在屏幕截图。

## 框选与恢复

截图时临时隐藏本程序原先可见的窗口，前置目标后采集一张冻结画面。高亮框标出目标客户区的可选范围，窗口外不能开始框选；拖到边界外时只截断选框，真实鼠标不受限制。Enter、双击选框或“完成”确认，Esc、右键、Alt+F4 或“取消”结束截图。完成、取消和异常统一恢复本程序原先可见的窗口，不复活已关闭窗口。

客户区不包含系统标题栏与边框，但应用自绘标题栏可能属于客户区。截图仍基于当前可见屏幕，不使用后台窗口渲染；其他置顶窗口遮挡不会因前置自动消失。窗口句柄、进程 ID 和窗口类共同校验，标题变化本身不会使同一窗口失效；目标关闭、身份变化、无法前置、没有可见内容或采集前后客户区变化时，明确失败，不切到其他窗口或交付失效图片，采集页已有图片保留。

窗口恢复使用异步请求，沿用 150 ms 截图准备间隔；后台最多再等待约 600 ms 检查可用内容区，每次间隔约 25 ms，取消会中断等待。这些是截图交互的等待，不属于播放器 delay。原生截图内部仍不能立即中断，晚返回结果由会话标识丢弃。

## 屏幕与 DPI

沿用既有单屏冻结框选。窗口跨屏或部分在屏幕外时，选择客户区可见面积最大的显示器，仅该屏幕上的可见内容允许框选；冻结层提示“当前屏幕可见部分”。完整窗口素材应先将窗口移入单屏。整个内容区都在屏幕外则失败。

Win32 客户区使用临时 Per-Monitor V2 线程 DPI 上下文查询物理坐标，并在同一线程的 finally 中恢复。Java 17 Windows 屏幕原点沿用物理原点，宽高按屏幕缩放；通过原生显示器范围和实际 Robot 高分辨率图像换算，向内取整，避免截入边框和窗口外像素，代价是边缘可能少一两个像素。截图像素与显示器尺寸差异超过舍入范围时拒绝本次截图。

参考：[Windows 前台窗口限制](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setforegroundwindow)、[线程 DPI 上下文及恢复](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setthreaddpiawarenesscontext)、[OpenJDK 17 Windows 屏幕坐标实现](https://github.com/openjdk/jdk17u/blob/master/src/java.desktop/windows/native/libawt/windows/awt_Win32GraphicsConfig.cpp)。

## 与录制、播放的关系

截图目标仅存在当前采集页内存，不写入 MR、个人配置或截图图片的隐藏元数据；不会更改录制目标、F10 录制截图、识别测试或正式播放的搜索范围，不在播放过程中新增激活窗口行为。截图仍作为普通 PNG 使用，也可继续进行独立 OCR 提取。

后续新增的[窗口内识别](window-recognition.md)需在图像动作中单独设置，并随 MR 保存；它不自动继承这里的临时截图目标。

本次没有新增运行依赖或升版。自动验证仅使用假窗口列表、合成捕获源、离屏事件及不显示的自建窗口，实际窗口枚举、最小化恢复、前置、真实屏幕图像、跨屏不同 DPI 及遮挡仍需人工验收。具体测试与日志见 [自动测试记录](automated-tests.md)。
