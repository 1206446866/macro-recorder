# Windows 单实例启动

实现日期：2026-10-24。仅处理启动互斥及已有窗口唤起，不修改宏格式、录制或播放流程。

## 行为与实现

- `MacroApplication` 在 OpenCV 预加载、`MacroFrame` 和监听器初始化之前获取单实例保护。第二次启动通知已有实例后直接返回，不创建第二个主窗口。
- `WindowsSingleInstance` 使用带当前用户 SID 的 `Local` 命名互斥量，同一用户、同一登录会话内共享身份；身份不依赖安装目录或版本号。
- 互斥量采用非线程所有权的句柄存活保护。初始化中或异常退出资源回收期间，启动线程最多等待 5 秒，并重新尝试原子获取；不会因通知窗口尚未出现而放行第二个实例。超时或原生错误使用现有深色错误弹窗反馈。
- 独立的 message-only 窗口接收通知，不替换 AWT 或紧凑录制标题栏的窗口过程，不占网络端口。原生回调保持强引用，窗口与窗口类在所属线程销毁；应用退出时关闭句柄，进程异常终止后由系统回收。
- 第二个进程尝试将前台权限授予已有实例，再发送异步消息；已有实例在 Swing EDT 上复用 `WindowManager.restoreAndActivate()`，恢复当前同一个窗口。录制紧凑模式保持紧凑模式，播放及录制状态不变，不调用停止、暂停或重新加载宏。
- 截图等流程主动隐藏窗口期间，不强制显示被隐藏的主窗口，以保留现有截图行为。

该机制自新版启动后生效。验收前应先正常退出未使用单实例机制的旧版进程，再运行新版。

## 验证边界

`WindowsSingleInstanceTest` 使用唯一实例标识、真实 Windows 互斥量/消息窗口及独立 JVM，覆盖重复启动跨进程通知、并发启动唯一主实例、正常退出重新获取、异常终止立即重启，以及回调异常后保护和通知仍有效。不创建应用窗口、不读个人配置、不发送键鼠输入。非 Windows 平台明确跳过这 5 项原生测试。

最终定向测试 8 项、完整测试 75 项，失败/错误/跳过均为 0，退出码 0；`mvn compile` 退出码 0。实际命令、时间和日志见 [本轮自动测试记录](automated-tests.md)。

真实 Windows 11、150% DPI 人工验收仍需确认：

1. 连续或同时双击启动，只保留一个主窗口；新增启动进程完成通知后退出。
2. 主窗口最小化或被其他应用覆盖时，再次启动能恢复并前置；原最大化状态保留。
3. 录制、暂停及播放期间再次启动，仍使用原窗口，运行状态不变；紧凑模式、尺寸与置顶行为保留。
4. 正常关闭后可以重新启动；异常终止后可以重新启动，无需删除任何锁文件。
5. 检查 Windows 实际前台激活效果。自动原生消息测试不等于可见窗口已获前台权限。

Windows 前台权限规则见 [AllowSetForegroundWindow 官方说明](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-allowsetforegroundwindow)。
